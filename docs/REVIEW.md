# Независимая проверка

Проверяющий агент: `research_reviewer`. Область: безопасность персональных данных, целостность сценариев, доступность и честность демонстрации. Этот документ разделяет статическое чтение кода и реально выполненные проверки; отсутствие замечаний не является полной сертификацией безопасности или WCAG.

## Текущая регрессия после аудита — 15 ноября 2026

Основной агент исправил воспроизведённые ошибки переходов, навигатора, повторной отправки задач, результатов зачёта, лимита общих демоаккаунтов, валидации причины отпуска и ссылок в PDF. Эта проверка не приписывается прежнему независимому агенту: ниже сохранён его исторический отчёт первой версии.

- Сборка успешна; серверные проверки **35/35**, полный браузерный прогон **32/32**, включая основные сценарии на 360 px.
- Потеря и повреждение ответа после успешной записи не создают вторую задачу при повторе; ключ сохраняется в SQLite и переживает перезапуск. Конфликт ключа — 409, повтор после удаления — 410, ключи разных пользователей разделены.
- Архив доступен только владельцу с CSRF; незавершённую заявку архивировать нельзя. Готовый документ и история остаются доступны, лимит освобождается. Мобильный архив проверен axe по WCAG A/AA; это не полная сертификация.
- Старая база обновляется без сброса заявок, баллов, прочтения и личного плана. Ранее записанный явный результат аттестации сохраняется.
- Новый серверный набор: [audit.test.mjs](../tests/audit.test.mjs). Новый браузерный набор: [audit.spec.js](../tests/e2e/audit.spec.js). Свежие снимки и процесс — в [PROCESS.md](PROCESS.md).
- Хостинг исключён пользователем из задачи; публикация и доступ из России остаются неподтверждёнными.

## Статическое ревью

14 ноября: прочитаны `AGENTS.md`, контракт модулей, схема БД, seed-данные, `server/app.mjs` и интеграционные API-тесты. SQL helpers включают `user_id` при чтении и обновлении личных записей; HTML-документ экранирует пользовательский текст. Проверены два разных вымышленных аккаунта, salted scrypt-хеши, отдельные сессии и идемпотентность.

Рекомендации ревьюера по дополнительным границам превращены в `tests/security.test.mjs`: отсутствие plaintext-паролей в БД, `Secure` при production-конфигурации, истечение сессии, конфликт повторного ключа с другим содержимым, JSON 404 для неизвестного `/api/*`.

## Выполненные проверки

- `npm run build`: production-сборка завершилась успешно.
- Финальный `npm test`: **21/21** результатов Node runner (19 дочерних проверок и 2 родительских блока), **0 failed, 0 skipped**. Отдельный `tests/security.test.mjs` содержит 9 дочерних проверок безопасности; все выполнены.
- Финальный `npm run test:e2e`: **20 passed за 35,9 с**, без ошибок и пропусков: 6 функциональных сценариев и 14 автоматических axe-сканирований. Ревьюер прочитал финальный лог, а не только сообщение об успехе.
- 6 браузерных сценариев покрывают неверный/верный вход и смену аккаунта, ошибку загрузки с повтором, задержанный ответ после logout, расписание/ICS/оценки, сохранение и приватность заявки/документа, чтение уведомлений и все разделы при 360 px.
- Axe проверяет вход и 7 разделов на 1440 px, а также вход и 5 разделов на 360 px по тегам WCAG 2 A/AA и 2.1 A/AA. В выбранных состояниях автоматических нарушений не найдено. Это не полная сертификация WCAG: ручная работа со скринридерами и реальные мобильные устройства не проверены.
- Независимый security suite проверяет значения password_hash/token_hash в изолированной in-memory БД, флаги cookies, отклонение login-CSRF, некорректный JSON и типы полей, конфликт Idempotency-Key, экранирование HTML в скачиваемом файле, JSON 404 для неизвестного API, `Cache-Control: no-store`, ротацию и истечение сессии.
- Тесты не используют рабочую базу `data/orbita.sqlite` и не вносят изменения в демонстрационные аккаунты рабочего приложения.

## Неподтверждённые пункты

Публичный HTTPS URL, доступ из России, резервное копирование на реальном сервере и непрерывная работа до 28 ноября требуют внешнего развёртывания. Docker-инструкция и локальная проверка не являются доказательством выполнения этих пунктов. Функциональные мобильные сценарии проверены в Chromium с viewport 360 px; визуальные снимки desktop/mobile просмотрены тимлидом. Проверки реальных iOS/Android-устройств и ручной аудит со скринридером не проводились.
