# Подключения и запуск «Орбиты»

По умолчанию приложение работает без внешних ключей. Telegram/VK сохраняют демонстрационные события локально, общежитие использует демооплату без карты, помощник — локальные сценарии, поиск — цитаты из документов. MCP при этом является работающим локальным сервером протокола. Адаптеры не означают автоматически созданного бота, магазина, доступа к модели или опубликованного сайта.

Все данные конкурсные и вымышленные. Посетители с одним публичным демологином видят одни загрузки и подключения и могут отзывать его токены. Для показа используйте только учебные/вымышленные документы без персональных сведений и секретов. Настоящая привязка мессенджеров по умолчанию выключена. Внешних ключей в этой итерации нет: настоящая отправка, вызов Yandex и операция тестового магазина не объявляются проверенными.

## Локальное приложение

Нужен Node.js 24. Из корня проекта:

```sh
npm ci
npm run dev
```

Интерфейс: `http://localhost:5173`, API: `http://localhost:3001`. Vite проксирует `/api` и `/mcp`. Альтернатива — собранный интерфейс и API на одном порту:

```sh
npm run build
npm start
```

Теперь `npm start` и сервер внутри `npm run dev` автоматически читают необязательный `.env`. Для настройки скопируйте [`.env.example`](../.env.example) в `.env`, измените нужные значения и перезапустите процесс. Уже заданное окружение процесса имеет приоритет. `npm run dev` сохраняет API-порт 3001 для прокси; `npm start` читает `PORT` (по умолчанию 3001).

Секреты — только серверные переменные без префикса `VITE_`. `.env` исключён из Git. `DATABASE_PATH` позволяет выбрать файл SQLite; без него используется `data/orbita.sqlite`. Сохраняйте этот файл между запусками; удаление базы не является способом обновления проекта. Для локального HTTP оставьте `APP_ORIGIN` незаданным, `COOKIE_SECURE=false`, `TRUST_PROXY=0`. Настройки внешнего HTTPS адреса описаны в [DEPLOYMENT.md](DEPLOYMENT.md); хостинг в эту доработку не входит.

Войти можно как `alisa@demo.orbita` или `mark@demo.orbita`, пароль обоих `Orbita2026!`. Это публичные вымышленные аккаунты, а не образец управления настоящими студентами.

## MCP по HTTP

1. Войти в приложение → «Подключения» → MCP. Дать подключению понятное имя и выбрать только нужные разрешения. Для просмотра расписания достаточно `schedule:read`.
2. Создать токен и сохранить его в защищённых настройках своего MCP-клиента. Интерфейс показывает секрет один раз; сервер хранит хеш. Токен живёт 7 дней. Для его замены выпустите новый, старый отзовите в том же разделе.
3. Подключить клиент, поддерживающий **Streamable HTTP** и пользовательский заголовок `Authorization`. Для запущенного локального API адрес — `http://127.0.0.1:3001/mcp`; интерфейс также показывает свой доступный endpoint.

Пример формы настройки для клиентов с `mcpServers` (синтаксис конкретного клиента может отличаться):

```json
{
  "mcpServers": {
    "orbita": {
      "type": "http",
      "url": "http://127.0.0.1:3001/mcp",
      "headers": {
        "Authorization": "Bearer <ТОКЕН_ИЗ_ИНТЕРФЕЙСА>"
      }
    }
  }
}
```

Угловые скобки — место для локальной настройки, не рабочий токен. Не включайте полученный секрет в репозиторий, снимки или текст запроса модели. Если клиент умеет хранить секреты отдельно, используйте это хранилище. Сервер не принимает токен в query string и не использует cookie браузера для MCP.

Это PAT/Bearer-авторизация, **без OAuth discovery и страницы OAuth-входа**. Клиент, требующий только OAuth, такой конфигурацией не подключится. Облачный клиент не видит localhost вашей машины: ему нужен достижимый HTTPS endpoint. Для внешнего домена сервер проверяет `APP_ORIGIN` и Host; произвольный Origin не допускается. Статический JSON-пример не доказывает успешное подключение конкретного клиента.

Протокол обслуживается через POST. Для ручных диагностических JSON-RPC запросов нужны `Content-Type: application/json` и `Accept: application/json, text/event-stream`; нормальное согласование `initialize` и версии делает SDK клиента. Авторизованный GET `/mcp` возвращает 405: постоянный SSE-поток здесь не используется. Открытие endpoint как обычной страницы в браузере не является проверкой MCP.

## MCP через stdio-мост

Если локальный клиент запускает MCP-процесс через stdio, используйте [scripts/mcp-stdio.mjs](../scripts/mcp-stdio.mjs). Он пересылает инструменты в уже работающий HTTP-сервер; отдельной базы, пользователей или обойдённой авторизации у него нет.

Передайте процессу через настройки клиента:

- `ORBITA_MCP_URL` — адрес `/mcp`; по умолчанию `http://127.0.0.1:3001/mcp`.
- `ORBITA_MCP_TOKEN` — персональный токен, выданный интерфейсом.

Пример для локального клиента:

```json
{
  "mcpServers": {
    "orbita": {
      "command": "node",
      "args": ["/АБСОЛЮТНЫЙ/ПУТЬ/К/ПРОЕКТУ/scripts/mcp-stdio.mjs"],
      "env": {
        "ORBITA_MCP_URL": "http://127.0.0.1:3001/mcp",
        "ORBITA_MCP_TOKEN": "<ТОКЕН_ИЗ_ИНТЕРФЕЙСА>"
      }
    }
  }
}
```

Путь должен указывать на этот проект с установленными `node_modules`. Команда `npm run mcp:stdio` запускает тот же мост из корня проекта; для запуска непосредственно MCP-клиентом предпочтительнее показанный `node`, чтобы служебный вывод npm не попал в протокольный stdout. Если клиент запускает npm, используйте `npm run --silent mcp:stdio` и правильную рабочую директорию.

В отличие от веб-сервера, мост **не читает `.env` автоматически**: переменные поступают из окружения локального клиента. Не кладите личный токен в общую серверную конфигурацию. Мост разрешает HTTPS либо HTTP только для localhost/127.0.0.1/::1. Он должен оставаться запущенным, пока клиент пользуется инструментами.

### Инструменты и права

| Право            | Инструменты                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------- |
| `profile:read`   | `get_profile`                                                                               |
| `schedule:read`  | `get_schedule`                                                                              |
| `bookings:read`  | `list_rooms`, `get_room_availability`, `list_my_bookings`                                   |
| `housing:read`   | `get_housing`                                                                               |
| `knowledge:read` | `search_documents`                                                                          |
| `requests:write` | `prepare_request`, затем `confirm_action` для этой заявки                                   |
| `bookings:write` | `prepare_booking`, `prepare_booking_cancellation`, затем `confirm_action` для этой операции |

`confirm_action` принимает `actionId` и `confirmed: true`; права на конкретный тип операции проверяются снова. Клиент обязан сначала показать человеку `summary` и получить согласие. Не включайте автоматическое подтверждение записей: булево поле в вызове модели само по себе не доказывает волю человека. Подготовленная операция живёт 10 минут и привязана к инициировавшему токену; другой токен или браузер не подтвердит её. Повтор подтверждения возвращает сохранённый результат. Инструментов оплаты, выполнения команд или произвольного SQL нет.

Расписание и бронирования используют демо-неделю 16–22 ноября 2026. По умолчанию `get_schedule` запрашивает текущую дату по Москве. Поле `available` показывает, есть ли данные расписания на эту дату, даже если список занятий пуст. Примеры вопросов: «Покажи расписание на 17 ноября 2026», «Найди правила бронирования», «Проверь свободное время переговорной». Подготовленная через MCP и затем подтверждённая бронь появляется в «Кампусе».

## GigaChat в Навигаторе

Задайте `GIGACHAT_CREDENTIALS` (готовый ключ авторизации Base64 из кабинета GigaChat API, без префикса `Basic`) и `GIGACHAT_SCOPE` (`GIGACHAT_API_PERS`, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP` по типу проекта). `GIGACHAT_MODEL` по умолчанию равен `GigaChat-3-Pro`. Для Ultra укажите `GigaChat-3-Ultra`, если она доступна вашему проекту. Адаптер обменивает ключ на временный токен и использует нативный API Сбера. Навигатор показывает модель, указанную провайдером в принятом ответе, включая версию, если она есть. Если провайдер отклонит модель, подменит её или вернёт неподходящий ответ, Навигатор покажет локальный результат и пояснение. [Авторизация API Сбера](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api), [список моделей проекта](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/get-models).

Включите «Разрешить отправку вопросов в GigaChat» в Навигаторе. Флажок выключен при каждом новом открытии раздела. Сбер может получить текущий вопрос, до 320 символов предыдущего вопроса по той же теме, описания страниц и до трёх цитат из общих демодокументов. Предыдущий вопрос берётся из диалога этого аккаунта и используется для коротких уточнений, если он уже был обработан GigaChat с разрешения пользователя. Контекст удаляется вместе с диалогом после 30 минут бездействия при очередном обращении к Навигатору. Текст ответов, записи аккаунта, загруженные документы и черновики действий не входят в запрос к GigaChat. Вопросы по найденным загрузкам получают локальные цитаты.

Навигатор ищет по описаниям страниц и по базе знаний, а сервер проверяет идентификаторы источников и подставляет ссылки на реальные разделы и документы. Вопросы по данным аккаунта и подтверждение действий остаются локальными. Вызовы функций GigaChat отключены через `function_call: "none"`. Настройки GigaChat имеют приоритет перед Yandex. Если они указаны частично, Навигатор переходит в локальный режим. [Режимы работы с функциями GigaChat API](https://developers.sber.ru/docs/ru/gigachat/guides/functions/function-calling-modes).

На одну базу SQLite действуют скользящие лимиты в 6 внешних попыток за минуту и 60 за 24 часа для всех аккаунтов вместе. Лимиты сохраняются при перезапуске. Один процесс обрабатывает один внешний вопрос одновременно. OAuth и генерация укладываются в общий таймаут 8 секунд, без автоматического повтора. Размер запроса ограничен 8 КиБ, каждый ответ провайдера — 32 КиБ, генерация — 320 токенами. При превышении лимита или неподходящем ответе доступны локальные подсказки и цитаты.

Проверка цепочки TLS и имени хоста включена. Если нативный API требует сертификат НУЦ Минцифры, получите проверенный PEM по документации провайдера, сохраните вне репозитория и задайте абсолютный путь в `GIGACHAT_CA_FILE`. Доверие к этому PEM добавляется только для запросов GigaChat. Подробнее о монтировании файла см. [инструкцию Docker Compose](DEPLOYMENT.md). [Сертификаты GigaChat API](https://developers.sber.ru/docs/ru/gigachat/certificates).

В проверке предыдущего режима выбора раздела 19 ноября 2026 использовали подставные ответы OAuth и чата, чтобы проверить общую квоту, два студенческих аккаунта, перенос аудитории, неделю без данных и переход в локальный режим. Прошли 91 тест Node и 46 браузерных тестов Playwright. В отдельном прогоне Chromium на ширине 360 px проверены имя модели в ответе и подпись локального режима. Локальный HTTPS-сервер подтвердил проверку цепочки и имени хоста. Контейнер проверен без исходящей сети и с тестовым CA. В этой проверке рабочий ключ и внешние запросы к Сберу не использовались.

Повторить тесты адаптера и маршрута можно командой `node --test tests/gigachat.test.mjs tests/assistant.test.mjs tests/knowledge.test.mjs`. Для ручной проверки запустите `npm run build && npm start`, войдите в демоаккаунт, разрешите отправку и задайте «Что ты умеешь?», затем «Где получить справку?» и «Сколько дней?». Проверьте имя модели, переход в раздел заявок и ссылку на пункт документа. Задайте «Какие пары в понедельник?» и убедитесь, что расписание показано как локальный ответ. Приёмочные тесты подставляют ответы провайдера. Доступность живой генерации зависит от проекта GigaChat и его модели.

## Yandex AI и RAG

В `.env` задаются все три значения: `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, `YANDEX_MODEL_URI`. Используйте каталог и ключ своего сервисного аккаунта с нужным доступом. В [официальном каталоге](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models) на дату исследования опубликован URI Qwen `gpt://<folder_id>/qwen3.6-35b-a3b`; это проверенный пример, а не автоматически выбранная модель. Фактическую доступность и поддержку инструментов нужно проверить после получения доступа.

Адаптер отправляет запросы на `https://ai.api.cloud.yandex.net/v1/chat/completions` с `Authorization: Api-Key`, `OpenAI-Project` и `x-data-logging-enabled: false`. Ключи в браузер не передаются. Если пользователь включил отправку, провайдер может получить текущий вопрос и подходящие цитаты из общих демодокументов. При совпадении с загруженным файлом поиск возвращает локальные цитаты. Отключённое логирование не означает отсутствия этой передачи. Вызовы могут тарифицироваться провайдером.

У помощника перечислены доступные инструменты чтения и подготовки действия; отдельного инструмента автоматического подтверждения модели нет. Источники RAG берутся из той же базы знаний с проверкой владельца. Документы рассматриваются как данные, а не инструкции. Нет оснований в источниках — нет достоверного утверждения о правиле. При недоступной/несовместимой модели ответ переключается в локальный режим с пояснением. Удаление настроек возвращает полностью локального помощника.

## Telegram и VK

Встроенный журнал работает без ключей: «Подключения» → демонстрационное подключение канала → тестовое событие. Это локальная запись, не сообщение в мессенджере. На изменение заявки и брони создаются события для уже подключённого канала; старые уведомления не объявляются заново отправленными.

Для реальной привязки нужны HTTPS webhook, настройки нужного провайдера и явное `ALLOW_REAL_CHANNEL_LINKING=true`. На публичных общих аккаунтах оставьте значение `false`: другие посетители того же логина управляют теми же подключениями. Установка флага сама по себе не создаёт привязку.

**Telegram:** `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` без `@`, `TELEGRAM_WEBHOOK_SECRET`. Приложение требует случайный секрет 16–256 символов `A–Z a–z 0–9 _ -`. Администратор отдельно регистрирует через Bot API `setWebhook` HTTPS-адрес `<PUBLIC_ORIGIN>/api/channels/telegram/webhook`, передаёт тот же `secret_token` и подписку `allowed_updates: ["message"]`. Входящий запрос должен содержать `X-Telegram-Bot-Api-Secret-Token`.

После этого пользователь в приложении создаёт код, открывает предложенную ссылку бота и нажимает «Начать» в личной переписке. В webhook приходит `/start <code>`; обновление статуса в «Подключениях» показывает результат. Произвольный ID получателя в форме не вводится.

**VK:** `VK_GROUP_TOKEN`, положительный `VK_GROUP_ID`, `VK_WEBHOOK_SECRET` длиной от 16 символов, `VK_CONFIRMATION_TOKEN`, `VK_API_VERSION=5.199`. В сообществе настраиваются сообщения и Callback API на `<PUBLIC_ORIGIN>/api/channels/vk/webhook` с тем же секретом и событием `message_new`. При проверке сервера приложение сравнивает `group_id`/`secret` и возвращает строку подтверждения; для принятых событий отвечает `ok`.

В приложении пользователь получает код, открывает личные сообщения сообщества и отправляет код одним сообщением. Код одноразовый, живёт 10 минут и связан с текущей действующей сессией; выход до завершения потребует создать новый. Групповые беседы для привязки не подходят.

Очередь хранится в SQLite, обработчик запускается с веб-сервером. Успех означает принятие сообщения провайдером, не прочтение студентом. При подтверждённом ограничении частоты есть ограниченные повторы; после потери ответа возможен статус «Доставка не подтверждена» без автоматической повторной отправки. Так снижается риск дубликата у Telegram, где нет ключа идемпотентности `sendMessage`. Отключение канала отменяет ожидающие записи; последующая привязка не переправляет старую очередь другому адресату.

## Общежитие и YooKassa

`PAYMENTS_MODE=demo` — режим по умолчанию: только вымышленные счета, локальная смена статуса и учебная квитанция. Карта не вводится, деньги не списываются.

Для тестового адаптера нужны `PAYMENTS_MODE=yookassa-test`, `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`, `YOOKASSA_RETURN_URL`. Используйте только отдельный тестовый магазин. Приложение дополнительно принимает ключи с префиксом `test_` и отклоняет другие до запроса — это консервативное ограничение нашего адаптера. Основное подтверждение режима — `test: true` в ответе API. Возвратный URL задаётся сервером и должен быть HTTPS, например `https://your-domain.example/#housing`.

Создание checkout использует `POST https://api.yookassa.ru/v3/payments`, HTTP Basic и сохранённый `Idempotence-Key`. UI переводит на проверенную HTTPS-страницу провайдера. После возвращения необходимо обновить состояние платежа: сервер выполняет `GET /v3/payments/{id}`, сверяет тестовый режим, ID, сумму, валюту, счёт и владельца. Параметр в адресе браузера не может установить «оплачено».

При timeout/500 исход неизвестен: не создавайте произвольный новый платёж, используйте сохранённую операцию для повторной проверки. Провайдер сохраняет идемпотентность 24 часа; приложение хранит собственную связь счёта с платежом. Если ответ о создании так и не получен, повторный POST блокируется после 23 часов и нужна ручная сверка в тестовом магазине: новый ключ или очистка базы не являются безопасным восстановлением. Внешний webhook YooKassa в этой реализации не требуется: синхронизация запускается явной проверкой статуса. Промышленная бухгалтерия, настоящие списания и возвраты не входят в этот прототип.

## Документы и короткий показ без ключей

База знаний содержит вымышленные правила кампуса, общежития, справок, сессии и стипендии. TXT/MD или вставленный текст индексируются локально; PDF должен иметь текстовый слой, OCR сканов нет. Текущие ограничения: PDF до 2 МиБ и 80 страниц, извлечённый текст до 100 000 символов, до 30 своих документов и 500 000 символов на аккаунт. Ошибки формата, объёма и доступа возвращаются пользователю. Поиск — локальное ранжирование фрагментов, не облачная векторная база.

Демонстрация:

1. Войти Алисой. В «Подключениях» включить демоканал и создать тестовое событие; показать локальный статус.
2. В «Кампусе» выбрать 17 ноября, свободную комнату и интервал; подтвердить бронь, затем показать её и отмену. Занятость общая для обоих аккаунтов, ФИО других владельцев не раскрываются.
3. В «Общежитии» выполнить демооплату, повторно открыть счёт и скачать маркированную учебную квитанцию.
4. Найти «как заказать справку», открыть цитату и источник. Загрузить короткий вымышленный TXT, найти его и удалить. Марк не должен видеть этот документ.
5. Помощнику задать «Какое у меня расписание на 17 ноября 2026?». Затем «Закажи справку об обучении для учебного конкурса»; проверить карточку, подтвердить и открыть заявку.
6. Создать MCP-токен с правами чтения, подключить поддерживаемый клиент, запросить расписание и затем отозвать токен. Отозванный токен больше не должен работать.

Подробная приёмка — [FEATURES_PRODUCT.md](FEATURES_PRODUCT.md), первичные источники протоколов — [FEATURES_RESEARCH.md](FEATURES_RESEARCH.md). Живые подключения проверяются отдельно после появления доступов; тесты с подставленными ответами этого не заменяют.
