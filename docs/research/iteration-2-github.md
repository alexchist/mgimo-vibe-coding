## Проверка доступа и границы исследования

Этот агент самостоятельно проверил `git ls-remote` для Moodle, Canvas LMS и Frappe Education: все команды завершились с кодом 0. Публичные README, выбранные исходники и лицензии получены с HTTP 200. GitHub API вернул полные, не усечённые деревья Canvas (27 518 записей) и Frappe Education (960 записей). Пароли и дополнительные токены не запрашивались; применялся существующий HTTPS-маршрут среды с проверкой TLS.

Несколько первоначально предполагаемых путей дали 404: это неверные пути, а не отсутствие доступа. Например, Canvas planner находится в `ui/shared/planner` и `ui/features/widget_dashboard`, а Frappe portal — в `frontend`. Пути уточнены по деревьям репозиториев.

Приложения не запускались и пользовательские кабинеты чужих вузов не открывались. Здесь нет результатов пользовательского тестирования этих продуктов. Наблюдения относятся только к прочитанному коду указанной версии. Для текущих вопросов локальный запуск тяжёлых LMS не требовался: источники позволили проверить структуру состояний и действий без аккаунтов. Скрипты развёртывания сторонних проектов не выполнялись.

## 1. Canvas LMS: личное планирование отдельно от сдачи задания

Исследована версия `1c9f0bb8013ed69c4f2efe11fd483025469b7e6c`.

Реально прочитанные источники:

- [API личных заметок и отметок выполнения](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/ui/features/widget_dashboard/react/components/widgets/TodoListWidget/api.ts).
- [Загрузка, фильтры и страницы планировщика](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/ui/features/widget_dashboard/react/components/widgets/TodoListWidget/hooks/usePlannerItems.ts).
- [Создание личной заметки и обновление списка](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/ui/features/widget_dashboard/react/components/widgets/TodoListWidget/hooks/useCreatePlannerNote.ts).
- [Доступная отметка выполнения элемента](https://github.com/instructure/canvas-lms/blob/1c9f0bb8013ed69c4f2efe11fd483025469b7e6c/ui/shared/planner/components/PlannerItem/index.tsx).

**Наблюдение.** `PlannerOverride` содержит `user_id`, `marked_complete`, `dismissed` и временные метки. Отдельный `SubmissionStatus` содержит `submitted`, `graded`, `missing`, `late` и другие учебные статусы. Следовательно, в этой модели личная отметка планировщика и факт сдачи задания — разные сущности. Создание/изменение отметки идёт через `/planner/overrides`, а собственная задача создаётся через `/planner_notes` с заголовком, датой и необязательными деталями. Загрузчик поддерживает диапазон дат, незавершённые/завершённые элементы и размер страницы по умолчанию пять. У checkbox есть содержательная подпись для скринридера; состояние ожидания API предусмотрено отдельно.

**Решение для обсуждения в «Орбите».** Добавить небольшой личный план: учебные сроки из существующих данных плюс собственные дела. Использовать явную формулировку «Отмечено вами» и обратимое действие «Вернуть в план». Это не сдаёт работу преподавателю, не меняет оценку и не имитирует официальное подтверждение. Личные отметки сохраняются на сервере отдельно для каждого аккаунта. Собственные дела также сохраняются после перезагрузки.

**Что не переносим.** Полный набор типов LMS, наблюдение за другим пользователем, сложную пагинацию для небольшого демонстрационного списка, архитектуру React Query и сторонние компоненты. В нашем прототипе нет потребности в этих зависимостях. Обработка ошибки сохранения должна оставаться явной; существующий чужой код не считается образцом во всех деталях.

## 2. Moodle: временная шкала ориентирована на срок действия

Проверена ветка `MOODLE_500_STABLE`, разрешённая в commit `2d62d8b15891ee5c491e89713e079d96e47c918f`. Шаблон фильтра повторно получен по этому SHA и совпал с прочитанным содержимым ветки.

- [Основной блок Timeline](https://github.com/moodle/moodle/blob/2d62d8b15891ee5c491e89713e079d96e47c918f/blocks/timeline/templates/main.mustache).
- [Фильтр временного диапазона](https://github.com/moodle/moodle/blob/2d62d8b15891ee5c491e89713e079d96e47c918f/blocks/timeline/templates/nav-day-filter.mustache).

**Наблюдение.** Timeline объединяет фильтр дат, вид списка и поиск. В фильтре явно есть overdue, ближайшие 7 и 30 дней, 3 и 6 месяцев; выбранное состояние имеет доступные атрибуты. Это интерфейс поиска действий по сроку, а не только календарь аудиторных занятий.

**Решение для обсуждения в «Орбите».** Для небольшого объёма достаточно «В плане / Выполнено» и понятной сортировки по дате. Если нужен второй фильтр, использовать «На демо-неделе», а не автоматически показывать все исходные варианты Moodle. Срок в карточке должен включать абсолютную дату. Относительное «через N дней» рассчитывается от подписанной демо-даты, а не от часов браузера; статус «срок прошёл» определяется той же моделью.

**Что не переносим.** Шесть временных фильтров в компактный мобильный прототип, оформление Moodle и его код. Студенту не нужен новый сложный календарь поверх уже имеющегося расписания.

**Наблюдение.** README описывает расписание, посещаемость, платежи и оценки. Прочитанная главная строится вокруг календаря; события группируются по дате, предусмотрены переходы между месяцами. Не считать название файла или раздела доказательством готовой функции. В новый план попадают только действия, которые проходят полный путь: создать → сохранить → выполнить → отменить отметку → увидеть после повторного входа.

## Передача на критику

Наблюдения и предложения A+B («личный план» + «настоящий следующий шаг») отправлены агентам `creative_coordinator`, `critic_product` и `critic_technical`. Отдельно переданы ограничения: личное выполнение не равно сдаче работы; источник учебного срока не изменяется; данные изолированы сервером; демо-время едино; не добавлять все возможные функции одновременно.

## Второй проход: критика → уточнение → передача разработчикам

Координатор сообщил об explicit ACCEPT обоих критиков для уточнённого A+B. Это согласование объёма, а не утверждение о готовности реализации.

| Критика / ограничение | Уточнение исследовательской рекомендации |
| --- | --- |
| Личная галочка может быть воспринята как сдача учебного задания | Учебный элемент выводится из исходных данных и остаётся неизменяемым; отдельно хранится только личная отметка. Формулировка прямо указывает, что преподавателю ничего не отправлено. Все начальные отметки ложные. |
| Универсальный планировщик выйдет за объём демонстрации | Собственная задача имеет необязательный срок; если срок указан, он ограничен 16–22 ноября и это объяснено как граница демо. Без срока — отдельная понятная подпись, а не просроченная задача. Расширенные диапазоны Moodle не копируются. |
| Новая навигация может ухудшить основной мобильный сценарий справок | Основные заявки остаются в мобильной навигации; личный план встраивается без вытеснения обязательных разделов. |
| Новый объект рискует дублировать дедлайны или сбросить существующие данные | Общий серверный сборщик для GET и bootstrap; добавочные изменения БД без очистки существующих заявок; серверное владение и строгий разрешённый набор PATCH-полей. |
| Простой счётчик готовности может смешать личный прогресс и успеваемость | Отдельные «В плане / Выполнено», возможность вернуть дело в план, обновление ближайшего шага после отметки. Оценки и официальные состояния документов не меняются. |

Исследователь подтверждает суженный объём: **A — сохраняемый личный план, B — точный переход к ближайшему действию**. C (глобальная командная палитра) и D (заметки на каждой паре) отложены. Для этих решений подтверждающим источником остаётся разделение `PlannerOverride` и `SubmissionStatus` в Canvas; конкретная схема и UI «Орбиты» разрабатываются самостоятельно.

Разработчикам передаются источники, причины выбора и границы, а не задание воспроизвести чужие компоненты. Функциональную готовность, права доступа, сохранение, keyboard/mobile-сценарии подтверждают отдельные тесты команды. Исследование ограничено текущей итерацией; постоянный фоновый мониторинг после завершения сессии не заявляется.
