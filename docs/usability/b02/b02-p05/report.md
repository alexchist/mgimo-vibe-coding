# b02-p05 — личный план Алисы, телефон 390 px

Синтетический независимый UX-проход. Прочитана только инструкция участника, далее использован видимый браузер. Задача выполнена целиком: своё дело без срока создано, ближайшее эссе отмечено готовым и возвращено в работу, дело найдено после обновления и удалено.

## Фактический маршрут

- 002–005: экран входа, ввод предоставленного демологина и пароля, вход в кабинет Алисы.
- 006: «Мой следующий шаг» на главной открыл «Мой план» и выделил эссе со сроком 17 ноября — ближайшее из трёх учебных заданий.
- 007–010: «Новая задача» прокрутила к форме; ввела «Подготовить вопросы к семинару», нажала «Убрать срок» и «Добавить задачу». В списке появилась «Моя задача / Без срока», счётчик стал 0 из 4.
- 011: отметила эссе; список «В работе» убрал его, счётчик стал 1 из 4. Уведомление: «Личная готовность отмечена. Это не отправка работы».
- 012–013: выбрала «Все 4», нашла отмеченное эссе в конце списка и сняла отметку. Получила «Задача снова в работе», счётчик 0 из 4.
- 014–015: обновила страницу, прокрутила список. Своё дело сохранилось с подписью «Без срока»; эссе осталось без отметки.
- 016–017: нажала корзину у собственного дела, затем «Удалить» в подтверждении. Дело исчезло, осталось 0 из 3, уведомление «Личная задача удалена».
- Выполнен `finish`, сессия закрыта, артефакты сохранены в каталоге участника.

## Что поняла и что вызывало вопросы

Готовность не означает отправку преподавателю и не меняет оценки: это явно сказано над списком (006) и повторено после отметки (011). Внешнюю отправку или реальный университет не проверяла. Неожиданным было автоматическое переключение с «Все» на «В работе» после добавления задачи: готовое эссе затем исчезло из текущего списка, но кнопка «Все 4» помогла сразу его вернуть.

Поле необязательного срока изначально заполнено датой, поэтому для дела без даты потребовалось отдельное «Убрать срок». На снимке 007 дата показана как `11/16/2026`, хотя остальной интерфейс русскоязычный; текст под полем с датами демо-недели помог понять её.

## Предложения с основаниями

1. Оставлять необязательный срок пустым при открытии формы: в 007 мне пришлось специально убирать заранее заполненную дату для задачи без срока.
2. Показывать дату в привычном для русскоязычного интерфейса порядке: на просмотренном снимке 007 отображалось `11/16/2026`.
3. Сохранять выбранный фильтр после добавления дела либо явно сообщать о переключении: между 006 и 010 «Все» сменилось на «В работе», из-за чего отмеченное эссе исчезло в 011.

## Ошибки инструмента и ограничения

- В 011 команда `check` вернула timeout, хотя действие состоялось: счётчик и уведомление изменились, а в 012 эссе было отмечено. Повторно вслепую не нажимала.
- В 013 команда `check` сообщила, что состояние не изменилось, но дерево сразу показало снятую отметку и уведомление; обновление 014 подтвердило результат. Эти ошибки пульта сами по себе не считаю дефектами UI. Итоговый `finish` вернул `errors: []`, поэтому ошибки описаны здесь по фактическим ответам шагов.
- Использовался браузерный пульт с доступными именами элементов; он может сам прокручивать к цели. Оценки точности касаний пальцем не делаю. Невыполненных частей легенды нет; повторное обновление после удаления не проводилось.
