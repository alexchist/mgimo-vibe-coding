# Сбой подготовки стенда до пользовательских действий

Первые snapshot у p01–p03 вернули `No prepared session`. Причина — старый Node-процесс браузерного оператора после SIGTERM закрыл Chromium, но продолжил слушать 3199. Новый процесс получил EADDRINUSE, команды подготовки попали в старый и вернули `browser.newContext: Target page, context or browser has been closed`. Участники правильно остановились и запросили восстановление инструмента. Ни один экран приложения в этой попытке не был пройден.

Оркестратор завершил конкретный старый процесс, добавил явное завершение оператора по SIGTERM/SIGINT и пересоздал пять чистых сессий. Для каждой проверены настоящий экран входа, step 001 и отсутствие error. Участникам передана только готовность инструмента, никаких подсказок по сайту.

Отдельно p01 отправил буквально `SESSION` вместо собственного ID: оператор вернул `Invalid session ID`. В технической инструкции теперь явно написано, что это заполнитель. Это ошибка/неясность пульта, не интерфейса кабинета.

Обе причины исключены из оценки UX приложения. Отзывы участников сохраняют сведения о сбое; их первичные тексты не исправляются задним числом.
