# Батч 3 — контекст переходов и понятные действия

Исходная версия: `f01d086`. Пять новых участников завершили сценарии. Прочитаны пять отчётов, журналы и события пяти trace.zip; просмотрены изображения результата и затруднений. Ошибок страницы/пульта у участников этого батча нет.

| Наблюдение | Разбор и решение |
| --- | --- |
| p01 сразу увидел перенесённую пару со старой и новой аудиториями | Свежий участник без знания исправления подтвердил эффект предыдущего батча. Экспорт потребовал возврата наверх, но тупика не было; импорт календаря не проверялся |
| p02 удалил собственную памятку, повторный поиск дал другие документы | Удалённый документ действительно исчез. Вывод участника о неоднозначном завершении — не доказательство сбоя удаления: названия источников другие. Добавлено ясное пояснение, что поиск может совпасть по части слов; алгоритм и данные не менялись |
| p03 принял кнопку «Прочитано» возле нового уведомления за статус | Подтверждено снимком 006: одновременно есть «Новое» и «Прочитано». Действие переименовано в «Отметить прочитанным». Само сохранение прочтения после reload уже прошло |
| p04 «Подготовь… пока не подавай» не создаёт карточку проверки | Воспроизведено точной фразой из trace. Добавлена ограниченная поддержка явной подготовки; инструкция не подавать отделяется от назначения. Отрицание, вопрос и отмена не готовят новое действие; запись создаётся только отдельным подтверждением |
| p04 после «Открыть заявку» видит форму наверху, карточка ниже | Независимый браузерный тест воспроизвёл: фокус уже на карточке, но доля её видимости 0. Причина — поздний общий hashchange сбрасывал прокрутку после локальной фокусировки. Ссылки на конкретные объекты теперь сохраняют управление прокруткой своего раздела |
| p05 понял деморежим Telegram, но «Серверный адаптер» звучит технически | Маршрут включения → теста → отключения прошёл, реальной отправки не было. Текст теперь объясняет, что настоящие сообщения требуют настройки подключения администратором |

## Проверки

- Production-сборка успешна; полный серверный набор **101/101**.
- Новые проверки помощника до изменения воспроизвели 3 сбоя; после — **15/15** с прежним assistant-набором. Проверены чистое назначение, отсутствие заявки до согласия, чужое подтверждение и повтор без дубля.
- Браузерная регрессия перехода до исправления упала на видимости карточки, лог сохранён в `regression-before.txt`. После изменения **4/4** затронутых браузерных теста: переход к заявке, обе проверки расписания и desktop axe уведомлений.
- Отдельный проход в настоящем Chromium 360 px: кнопка отдельного прочтения работает, переполнения нет, axe нарушений выбранных A/AA-правил не нашёл. Новый запрос «Подготовь…» показал проверку назначения; после подтверждения заявка видна в области экрана. Снимки `review-notifications-mobile.png`, `review-prepare-before-confirm.png`, `review-request-in-view.png` просмотрены оркестратором.
- Ошибки проверки, не сайта: первый вспомогательный axe-скрипт использовал удобный `browser.newPage`, несовместимый с требуемым отдельным контекстом; ещё один запуск прервало переключение локального сервера. Они не учтены как успешные проверки или UX-дефекты. Повтор на готовом сервере с отдельным BrowserContext прошёл.

Пределы сохранены: помощник без ключей — ограниченный локальный сценарий, поиск — фрагменты документов, Telegram — только демонстрационная запись. Первичные отзывы не переписывались.
