# Независимые браузерные проверки — 17 ноября 2026

Начало: `git pull --ff-only origin feat/orbita-student-portal`, fast-forward `1a40615 → 3767fe7`. Доработки сохраняются локальными коммитами в этой же ветке; новая публикация и push не запрошены.

Это синтетические проверки агентами, не интервью с людьми и не статистическое доказательство удобства. Пять новых участников на батч получают только легенду, цель, публичный демологин и инструкцию браузерного инструмента. История команды, исходники, тесты и чужие отзывы им не передаются (`fork_turns=none`). В каждом батче используются GPT-6 Luna low, GPT-6.1 Sol low/medium, GPT-6 Sol medium, GPT-6 Astra high. Модель и reasoning — характеристики проверки, а не мера достоверности конкретного отзыва.

## Среда и свидетельства

Локальная собранная демоверсия: `http://127.0.0.1:3001`. У участников отдельные экземпляры той же сборки с чистыми SQLite-базами в памяти, отдельными Chromium-контекстами, московским временем и русской локалью. Мобильные и широкие экраны чередуются. Фиксированная учебная неделя приложения: 16–22 ноября 2026. Внешние провайдеры выключены.

В этой сессии нет инструмента управления общим рабочим столом. `scripts/usability-browser.mjs` предоставляет узкий интерфейс к настоящему Chromium: видимый текст/доступные имена, нажатия, ввод, прокрутка, клавиатура, загрузки. Он не предоставляет участникам исполнение JavaScript, исходники, чтение хранилищ или API приложения. Участник выбирает каждый шаг сам; это не заранее записанный сценарий. Ограничение: дерево доступности показывает и доступный текст ниже области просмотра; поэтому участники дополнительно смотрят реальные снимки. Headless-браузер не воспроизводит все особенности настоящего телефона.

Каждая папка участника содержит `actions.jsonl` с фактическими шагами, снимками и ошибками, последовательные JPEG, `trace.zip`, `summary.json`, независимый `report.md` и скачанные демофайлы при наличии. Следы содержат только вымышленные данные одноразового локального экземпляра; после `finish` его база и сессии уничтожаются. Пароль в журнале ввода маскируется. Секреты внешних сервисов не используются. Трейс открывается командой `npx playwright show-trace <путь/trace.zip>`.

Оркестратор отдельно проверяет отзывы по шагам/снимкам/трейсу, воспроизводит существенные находки, разделяет дефекты интерфейса, ошибки участника, ограничения инструмента и пожелания. Исправления проходят необходимые регрессионные проверки и визуальную проверку. Следующий батч начинается после локального коммита. Предел — десять батчей; одинаковые находки учитываются один раз, отсутствие новых проблем не превращается в выдуманные улучшения.
