# Инструкция независимому участнику

Это синтетическая проверка агентом, не настоящее интервью. Вы получаете отдельную легенду и цель. Выполняйте её самостоятельно, как впервые пришедший пользователь. Не ищите проблемы ради отчёта и не угадывайте, чего ожидают разработчики.

**Не читайте исходники, тесты, README, другие отчёты или задания участников. Не делайте запросов к API приложения, не пишите JavaScript/Playwright, не используйте DevTools и не общайтесь с другими агентами.** Читать разрешено только эту инструкцию и видимый браузер. Изменять можно только свой `report.md` через apply_patch. Никаких иных shell-команд, кроме браузерных команд ниже и первого чтения этой инструкции.

Сессия уже открыта. **В каждой команде замените слово `SESSION` своим идентификатором из задания, например `b02-p01`; буквально `SESSION` передавать нельзя.** Выполняйте действия через `functions.exec` → `tools.exec_command`, workdir `/workspace/mgimo-vibe-coding`, login:false. Это пульт настоящего Chromium, а не программирование сценария:

```text
node scripts/usability-browser.mjs SESSION snapshot
node scripts/usability-browser.mjs SESSION click '{"role":"button","name":"Видимое имя"}'
node scripts/usability-browser.mjs SESSION fill '{"label":"Видимая подпись","value":"Текст"}'
node scripts/usability-browser.mjs SESSION select '{"label":"Подпись списка","value":"Видимый вариант"}'
node scripts/usability-browser.mjs SESSION check '{"role":"checkbox","name":"Имя","checked":true}'
node scripts/usability-browser.mjs SESSION press '{"key":"Tab"}'
node scripts/usability-browser.mjs SESSION scroll '{"y":600}'
node scripts/usability-browser.mjs SESSION back
node scripts/usability-browser.mjs SESSION reload
node scripts/usability-browser.mjs SESSION finish
```

Цель для click/fill/press/check/select: `role`+`name` либо `label`, `placeholder`, `text`. `exact:false` допустим для видимого частичного имени. `nth:0` — первое из нескольких совпадений; неоднозначность честно отметьте. Можно нажимать существующие ссылки; угадывать скрытые URL нельзя. `start` повторно не вызывайте. Поле даты принимает `YYYY-MM-DD`. После действий проверяйте ответ: он содержит реальное дерево доступности, step, screenshot и скачанные файлы.

Посмотрите **минимум два настоящих снимка**, включая результат: `image((await tools.view_image({path:"путь из screenshot"})).image_url)`. Дерево доступности иногда включает содержимое ниже экрана, поэтому без изображений судить о видимости нельзя. Ошибка формата команды/неоднозначный селектор сами по себе не доказывают дефект UI. Ничего не исправляйте в приложении.

До 25 осмысленных действий (snapshots не считаются). Остановитесь при успехе или честном тупике; не просите подсказки по маршруту. `finish` сохранит trace.zip и закроет одноразовую базу. В сообщениях оператора иногда указывается exec session_id: дождитесь результата через write_stdin, не повторяйте действие вслепую.

Сохраните только свой Markdown-отчёт по пути из задания. Он должен содержать фактический маршрут с номерами step, ответ на задачу, выполненные и невыполненные части, что было непонятно, 0–3 предложения с доказательствами. Ошибки инструмента/ваши ошибки — отдельным пунктом. Укажите, какие изображения действительно посмотрели. Не утверждайте, что скачанный файл импортирован во внешнее приложение или что демодействие отправлено в настоящий университет. Final: краткий результат и путь отчёта.
