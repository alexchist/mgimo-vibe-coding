# Курсом

Ранее — «Орбита». Обновление названия и первого экрана: [дизайн-итерация 16 ноября](docs/DESIGN_ITERATION.md). Старые демологины, имя базы, `ORBITA_*` и package name сохранены для совместимости. Исторические материалы и вымышленные документы могут содержать прежнее название.

Рабочий конкурсный концепт «Цифрового деканата будущего»: учёба, расписание, документы и следующий полезный шаг в одном кабинете.

**Неофициальный сервис.** Все студенты, преподаватели и учебные данные вымышлены. Университетские системы, логотипы и настоящие аккаунты не используются. [Открыть кабинет](https://mykursom.ru) → «Алиса» или «Марк». Сегодняшний день определяется по московскому времени. Для проверки с исходниками см. [комплект для жюри](docs/SUBMISSION.md).

## Запуск

Нужен Node.js **24** (встроенный SQLite). Из корня репозитория:

```sh
npm ci
npm run dev
```

Vite слушает порт **5173**, API — **3001**. Для демо внешние ключи не нужны. При необходимости скопируйте `.env.example` в `.env` и заполните серверные настройки: `npm run dev` и `npm start` читают этот файл автоматически. Секреты не должны иметь префикс `VITE_` и попадать в Git. Для запуска собранного приложения:

```sh
npm run build
npm start
```

Собранный сайт и API работают на одном порту **3001**. База `data/orbita.sqlite` создаётся автоматически, включена в `.gitignore` и сохраняет заявки, уведомления, личный план, брони, демоплатежи, документы, подключения и сессии. Не удаляйте её при перезапуске. [Подробная настройка интеграций и MCP](docs/INTEGRATIONS.md).

## Тестовые аккаунты

| Логин               | Пароль        | Данные                                          |
| ------------------- | ------------- | ----------------------------------------------- |
| `alisa@demo.orbita` | `Orbita2026!` | Первый вымышленный студент                      |
| `mark@demo.orbita`  | `Orbita2026!` | Второй вымышленный студент с отдельными данными |

Это намеренно публичные демонстрационные аккаунты для жюри. Пользователи одного тестового аккаунта видят общие данные, загрузки и подключения этого аккаунта и могут отзывать его MCP-токены. Загружайте только учебные/вымышленные документы без настоящих персональных данных и секретов. Пароли не подходят для других сервисов. В базе хранятся scrypt-хеши, не открытые пароли. Настоящая привязка Telegram/VK по умолчанию выключена.

## Возможности

- Вход, выход и профиль; серверное разделение данных студентов.
- Расписание дня/недели, поиск, заметные переносы, экспорт календаря.
- Текущие баллы и результат аттестации показаны отдельно: «Ещё не проходил», «Зачтено» / «Не зачтено», результат экзамена. Сессия и условный калькулятор для экзаменационных дисциплин.
- Создание заявки, история статусов, сохранение между перезапусками, скачивание маркированного демодокумента. Готовые заявки можно перенести в архив с сохранением истории и документов; архив освобождает лимит в 200 заявок вне архива.
- Уведомления с отметками прочтения и точными переходами к заявке, учебному делу, дню расписания или сессии. Контекст ссылки сохраняется после обновления страницы.
- Главная с ближайшими задачами; помощник отвечает по данным аккаунта, ищет документы и готовит справки/брони с отдельным подтверждением. Без ключей работает обозначенный локальный режим; при серверной настройке доступен GigaChat или адаптер Yandex AI. На сайте кнопка «Спросить GigaChat» отправляет вопрос модели, а «Искать локально» работает без неё. Платёжных инструментов у модели нет.
- «Мой план»: свои задачи и учебные сроки, сохраняемые личные отметки, отмена выполнения и точные ссылки на дела. Отметка не означает сдачу работы преподавателю; учебные данные неизменны.
- Кампус: доступность вымышленных общих помещений, сохраняемые брони и отмена; сервер проверяет пересечения и лимиты.
- Общежитие: свои начисления, демооплата без карты и учебная квитанция. Отдельно подготовлен адаптер тестового магазина YooKassa; реальные списания не поддерживаются.
- База знаний: вымышленные правила, поиск с цитатами и загрузка TXT/MD/PDF с текстовым слоем. Документы разделены между аккаунтами; сканы без OCR не поддерживаются. При включённом Yandex найденные фрагменты используются для ответа RAG.
- Подключения Telegram/VK: локальная демонстрация, сохранённая очередь и журнал. Для внешней доставки нужны серверные ключи, webhook и подтверждение адресата одноразовым кодом.
- MCP: Streamable HTTP `/mcp`, персональные токены с правами, сроком и отзывом; локальный stdio-мост для совместимых клиентов. Поддерживаются чтение данных, подготовка и подтверждение действий. Это авторизация Bearer, без OAuth onboarding.
- Адаптивный интерфейс от 360 px и управление с клавиатуры.

Смена статуса заявки выполняется явной кнопкой демосимуляции. Никакие заявления в настоящий деканат не отправляются. Кабинет сотрудника не предусмотрен. Внешних ключей для этой итерации не предоставляли: реальная доставка Telegram/VK, вызовы Yandex и платежи тестового магазина не заявляются как проверенные. При включении Yandex вопрос и необходимые фрагменты данных отправляются провайдеру; интерфейс сообщает этот режим.

## Проверки

```sh
npm run build
npm test
npm run test:e2e
```

Браузерные тесты используют Chromium в `/usr/bin/chromium`; для другой установки задайте `CHROMIUM_PATH`. Например, установите Chromium средствами вашей ОС. API-тесты создают отдельные временные базы и проверяют вход, CSRF, чужие идентификаторы, заявки и сохранение после перезапуска. Браузерные тесты проверяют реальные сценарии, включая 360 px.

## Архитектура и безопасность

React + Vite, Express, SQLite. Сервер определяет владельца по сессии и добавляет его ID в каждый запрос к личным данным. Идентификаторы чужих объектов возвращают 404. Cookie HttpOnly / SameSite; изменения через браузер требуют CSRF-токен. Сессии ограничены по времени, в базе хранится хеш их случайного идентификатора. Пароли хешируются scrypt. MCP использует отдельные хешированные токены с выбранными правами на 7 дней; webhook проверяет секрет провайдера. Действия помощника привязаны к владельцу и инициировавшему подключению, истекают через 10 минут и требуют подтверждения. Ввод проверяется сервером. В продакшене необходимы HTTPS, `COOKIE_SECURE=true`, корректный `APP_ORIGIN` и доверие только своему reverse proxy.

SQLite и один сервер подходят для демонстрации и небольшой нагрузки. Горизонтальное масштабирование потребует PostgreSQL, общего хранилища сессий/лимитов, миграций и отдельного фонового обработчика документов. Такая миграция здесь не заявляется как выполненная; внешние сервисы для прототипа не нужны.
